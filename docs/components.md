# component reference

what each piece in this repo is and how it works. the long forms are in
[homebrew.md](homebrew.md), [syncsploit/README.md](../syncsploit/README.md) and
[rawplay/README.md](../rawplay/README.md).

## the boot chain

    nand: /packages/system/override/hmi_startup.sh     jailbreak/hmi_startup.sh
      |  mount the usb stick, hand over if there is a boot.sh
      v
    stick: /fs/usb0/homebrew/boot.sh                   stick/homebrew/boot.sh
      |  start the hmi with LD_PRELOAD=hmi-overlay.so, then start the launcher
      v
    hmi draws CarPlay/Apps plates    hmi-overlay.so + usb/hmi-overlay/ (baked frames)
    launcher swallows touches on them and runs the commands in buttons.txt
      |  CarPlay -> rawplay.sh     Apps -> main (the menu)
      v
    the menu runs the rows in apps.txt: rawplay, mediaplayer, doom, buswatch, iccbuttons, ...

## runtime (common/)

shared unit-side code moved out of the ICC2 SDK. every app links the pieces it needs; they are
small and `gc-sections` drops the rest.

| file | what |
|---|---|
| `jlog.c` | one append-only debug log for the whole chain. writes `/fs/usb0/homebrew/jailbreak.log`; when the stick is gone under the fd (a car wake), it falls back to `/tmp/jailbreak.log` and retries the stick every few lines, so `stickwatch.sh` can flush it back. C lines use uptime `[seconds.ms]`. |
| `hmictl.c` | hmi session control: `hmi_signal`/pause/resume (SIGSTOP the hmi + kill/restart `buttons` so no queued events replay), the touch-connector handoff, the `/tmp/hmi-stopped` and `/tmp/buttons-paused` markers, and `run_command_guarded()` - the car guard that watches ipc for audio-off-with-ignition-off or the panel power button and closes a command's process group so the unit can sleep. |
| `raw-usb.c` | the usb bulk transport rawplay uses: attaches the composite gadget's vendor interface through `libusbdi`, keeps an urb ring, handles the max-packet alignment and the direct-dma/staging paths. |
| `livi-usb.c` | the alternate transport with the same read/write shape (the one that includes real libc headers and builds against the ffmpeg shim). not linked by a client yet; `make` compiles it as a check. |
| `usbdi.h` | hand-written qnx usb ddk prototypes; the link-time stub comes from the ICC2 SDK. |
| `menu.c`, `menufont.c` | the homebrew ui: labels/tabs/status cards in a proportional bitmap. `menufont.c/.h` are generated by `mkmenufont.py` at build time and not tracked: the dump's Arial when the ICC2 SDK has it, otherwise a free metric-compatible font (Liberation Sans). used by the menu, buswatch, the syncsploit ui and mediaplayer. |
| `mkmenufont.py` | bakes the ui font bitmap (`menufont.c/.h`) from a ttf; run by `make`/`build.sh`, never checked in. |

## jailbreak/

| file | what |
|---|---|
| `hmi_startup.sh` | **the only file that goes on the unit.** pkgstart sources it in place of the hmi's startup. it restarts `io-usb_swsa` without `force_fs` (high speed), mounts the stick at `/fs/usb0`, runs `homebrew/boot.sh` when present, and reports "Jailbreak successful!" / "Jailbreak failed. \<reason\>" on the hmi's progress lines. it never needs a rewrite. |
| `mkhookblob.py` | bakes the hook into `out/hookblob.h` at build time, byte for byte, so the syncsploit ui can compare and install it with no stick file involved. |

## launcher/

`launcher.c` replaces the stock `touch_2_hmi_connector`: it forwards every touch to the hmi
except two zones over the CarPlay/Apps plates, which run the commands from
`stick/homebrew/buttons.txt` (defaults in the binary). each command runs in its own process
group under the car guard, with the hmi stopped and the touch device closed so the app owns
the screen; `hmi-overlay.loaded` names the hmi process to stop/resume.

## hmi-overlay/

`hmi-overlay.c` is an LD_PRELOAD shim loaded into the hmi by `boot.sh`. it redirects
`/usr/hmi/<asset>` opens to `$HMI_OVERLAY`, then `/fs/usb0/hmi-overlay`, then
`/tmp/hmi-overlay`, falling back to the unit's own file; it never claims the
`/tmp/hmi-overlay.loaded` marker from a live unrelated process, and ignores
`/usr/hmi/Audio/`. `mkhmiassets.py` bakes the two button plates into copies of the hmi's
theme frames (all three themes, day/night, every frame the hmi draws) into `usb/hmi-overlay/`;
`mkusb.py` runs it.

## hbmenu/

`homebrew.c` is the menu the Apps button opens (`usb/homebrew/main`). it matches the hmi's
menu style: `menu.raw` background (baked by `mkmenuassets.py`), the hmi's font, five rows a
page with scrollbar, and a "back" tab that restores and resumes the hmi. it stops the hmi
itself when launched by hand, saves/restores the frozen frame, and guards each app it runs.
the stick scripts live here too:

- `stick/homebrew/boot.sh` - the stick side of the hook: starts the hmi with the overlay,
  stops the stock touch connector, starts the launcher and `stickwatch.sh`.
- `stick/homebrew/stickwatch.sh` - keeps the stick mounted across a car sleep/wake (the
  stock media restart unmounts it), restarts the launcher if a wake killed it, and flushes
  `/tmp/jailbreak.log` back to the stick.
- `stick/homebrew/apps.txt` - one `label|command` per menu row.
- `stick/homebrew/buttons.txt` - `name|command` for the CarPlay/Apps plates.

## apps

| component | source | what |
|---|---|---|
| rawplay | `rawplay/rawplay.c` (unit), `rawplay/rawlink.c` (host) | uncompressed rgb565 frames the size/format of the panel over the composite gadget's vendor interface, touch/knob/buttons back. no codec: the player dma's bulk-in urbs into the scanout mapping (`--direct`) or copies through the staging ring (`--stage`, the real-car default). the host also provides the functionfs gadget + mass storage (`gadget`/`run`) or takes a stream from weston (`stream`). see `rawplay/README.md`. |
| mediaplayer | `mediaplayer/mediaplayer.c` | ffmpeg file browser/player: lists `/fs/usb0`, plays what the ICC2 ffmpeg port demuxes, decoder steps down to half size when the arm11 cannot keep up. links the ICC2 SDK's `libav*` build. |
| terminal | `terminal/terminal.c` | a shell on the panel: framebuffer vt100 terminal + touch keyboard, the unit's fbterm + fbkeyboard. no pty on the unit, so it spawns `/bin/sh -i` on pipes (posix_spawn) and does the prompt, echo, editing, history and ctrl-c itself. keyboard toggles between 100x17 and 100x30. run by `apps/terminal.sh`. |
| iccbuttons | `iccbuttons/iccbuttons.c` | maps front-panel and steering-wheel bits to names, shows the hmi event ids the stock buttons app fires, saves an `INPUT_BUTTON` table. |
| buswatch | `buswatch/buswatch.c` | live scope for uart3 and pmm's standby pin (gpio3 bit 26): decode tables baked from the ICC2 SDK's `qemu/v850_messages.py` (`mksignals.py`), every byte/bit edge timestamped, log flushed on a pin edge so a sleep leaves the evidence. |
| doom, fbdemo | the ICC2 SDK's `sdk/doom`, `sdk/fbdemo` | the game and a framebuffer smoke test; built in the SDK, copied into the stick. |

## syncsploit/

the installer and the factory path it rides. `payload.sh` is the script the stock
`synctool_check_and_exec.sh` runs as root from the stick; it lifts the connector's key out of
`/dev/shmem/passwd`, then `exec`s the ui (`syncsploit/syncsploit.c`) which shows
not-jailbroken / jailbroken / different-jailbreak, and on **Jailbreak** writes the embedded
hook to `/packages/system/override/hmi_startup.sh`, verifies it and reboots. `findkeys.py`,
`mkexploit.py` and `opensslenc.py` build the stick and handle both validation routes (the
shadow-tool PATH route and the real key route); `synctool/` is the ready-made tree, refreshed
by `make synctool` and copied to `/synctool` on the assembled stick by `make stick`/`build.sh`;
the `test_*.py` scripts run the whole thing in the ICC2 SDK's emulator, including against a stock
unit. details, including the reverse engineering, are in
[syncsploit/README.md](../syncsploit/README.md).

## build/stick tooling

a complete `usb/` tree and `usb.img` will be included in the GitHub releases, so building is
not required in general; build only to change code or bake the art from your own dump.

- `build.sh` - one-shot build: locates the ICC2 SDK, checks the tools, builds the unit apps and the
  host tools, refreshes the synctool tree and assembles the complete stick (`usb/`) and
  `usb.img`. `--no-host`, `--no-stick`, `--clean`, `-j N`.
- `config.mk` - finds the ICC2 SDK (`ICC2_DIR`) and derives the shared flags; includes
  `$(ICC2_DIR)/sdk/config.mk`.
- `Makefile` - unit apps, `host`, `synctool`, `stick`, `clean`.
- `mkusb.py` - bakes the generated art (from the ICC2 SDK's dump when present) and packs `usb/`
  into `usb.img` (mbr + one fat32 partition; the unit ignores a bare filesystem). `dd` it
  to a stick, or copy `usb/` onto any fat32 stick.
- `stick/` - the tracked base of the stick: `homebrew/boot.sh`, `homebrew/stickwatch.sh`,
  `homebrew/apps.txt`, `homebrew/buttons.txt` and the app launcher scripts under
  `homebrew/apps/`. `make stick` copies it to `usb/` and adds the built programs.
- `usb/` - the assembled stick output (base + built programs + the `/synctool` installer
  tree + baked art/`menu.raw`), produced by `make stick`/`build.sh`; entirely git-ignored.

nothing under `usb/hmi-overlay/` or `common/menufont.c` is ever committed - those are baked
from the (proprietary) firmware dump locally and are git-ignored.
